From Coding Assistance to Agentic Engineering

Introduce the session as a practical progression from inline assistance to governed agentic engineering.

Where are you today?

Calibrate the room. Emphasize that progress does not require adopting every feature.

One product, three capability layers

Distinguish synchronous help, delegated execution, and the customization needed to fit a team and codebase.

Model, harness, tools, and controls

Explain that where the harness runs is separate from where the model runs.

Which model? Start with Auto

Position Auto as the default and manual routing as an intentional exception.

Choose the surface by where work should happen

Use the priority-filtering example to show how the same task changes across harnesses.

Better prompts are better task definitions

Read the strong prompt as an executable task definition rather than prose crafted for an AI.

Context shortcuts worth learning

Encourage participants to discover commands in their current surface rather than memorize a universal list.

The customization ladder

Explain the distinct role of each customization primitive and why instructions are the best starting point.

Built-in tools, MCP, and deterministic hooks

Stress that fewer tools improve selection and reduce risk; capability is not the same as intelligence.

Autonomy is a dial

Frame autonomy as a dial selected for the task, not a maturity ladder everyone must climb.

GitHub is the control plane

Treat agent output as contributor output. Generated code still requires validation and accountable review.

Agentic Engineering with Spec Kit

Differentiate what and why in the specification from technology decisions in the plan.

Your homework

Ask each participant to choose one behavior to change after the session.
